To configure Firebase for your Flutter application on both Android and Web, follow these steps. Since you are using **Google Sign-In** and **Firestore**, the configuration must ensure that the authentication tokens match the Firebase project.

### 1. Firebase Console Setup

1.  Go to the [Firebase Console](https://console.firebase.google.com/).
2.  Create a new project (e.g., "Krag-KMS").
3.  Enable **Firestore Database** in the "Build" menu.
    - Choose a location close to your users.
    - Start in **Test Mode** for now (we will set secure rules in Step 5).
4.  Enable **Google Authentication**:
    - Go to **Authentication** > **Sign-in method**.
    - Enable **Google**.
    - Ensure the "Project support email" is set.

---

### 2. Install & Run FlutterFire CLI

The modern way to configure Flutter is using the CLI, which generates the necessary configuration files automatically.

1.  **Install the CLI** (if you haven't):
    ```bash
    dart pub global activate flutterfire_cli
    ```
2.  **Login to Firebase**:
    ```bash
    firebase login
    ```
3.  **Configure the project**:
    Run this command from your project root:

    ```bash
    flutterfire configure
    ```

    - Select your project.
    - Select **android** and **web**.
    - This will generate `lib/firebase_options.dart`.

---

### 3. Android Specific Configuration

Android requires a SHA-1 fingerprint for Google Sign-In to work with Firebase.

1.  **Generate SHA-1**:
    ```bash
    cd android
    ./gradlew signingReport
    ```
    Look for the `SHA1` under `debugAndroidTest`.
2.  **Add SHA-1 to Firebase**:
    - In Firebase Console, go to **Project Settings** (gear icon).
    - Select your **Android App**.
    - Click **Add fingerprint** and paste your SHA-1.
3.  **Download `google-services.json`**:
    - The CLI usually handles this, but ensure `android/app/google-services.json` exists.

---

### 4. Web Specific Configuration

For Web, the CLI generates the config in `firebase_options.dart`. However, ensure your OAuth redirect URI is whitelisted.

1.  In the [Google Cloud Console](https://console.cloud.google.com/), go to **APIs & Services > Credentials**.
2.  Find the **OAuth 2.0 Client ID** created for the Web application.
3.  Add your authorized redirect URIs (e.g., `http://localhost:5000/auth.html` or your production domain).

---

### 5. Firestore Security Rules

Since your data is end-to-end encrypted, Firestore only sees binary blobs. However, you must still restrict access so users can only read/write their own data.

**Note:** The current `FirestoreAdapter` uses a flat `krag-vault` path. For production, you should modify the adapter to include the user's UID in the path (e.g., `users/{userId}/vault/docs`).

**Recommended Rules:**

```javascript
service cloud.firestore {
  match /databases/{database}/documents {
    // Allow users to access only their own vault data
    // This assumes you update the path to include the UID
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }

    // Current implementation fallback (if using shared root)
    match /krag-vault/{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
```

### 6. Initialize Firebase in `main.dart`

Update your `main()` function to initialize Firebase before the app starts.

**File: lib/main.dart**

```dart
import 'package:firebase_core/firebase_core.dart';
import 'firebase_options.dart'; // Generated by FlutterFire CLI

void main() async {
  WidgetsFlutterBinding.ensureInitialized();

  // Initialize Firebase
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );

  runApp(
    const ProviderScope(
      child: KragApp(),
    ),
  );
}
```
